# 顶栏授权徽标（授权状态 + 剩余天数 + 点击激活）修改计划

> 版本目标：**vc48 / 1.4.18**（vc47 已发布，vc42~47 占号 ⇒ 本次用 48）
> 状态：**计划待批**（本文未改任何代码）

---

## 1. 需求与口径确认

用户原话：

> 授权信息放到顶栏抖加加的旁边 就提示授权与否还有剩余天数（如果有授权的话，没有就不显示 ），点击这个字就弹窗输入授权密钥

按此确认三条口径（如理解有偏差请指出）：

| 项 | 口径 |
|---|---|
| 位置 | 顶栏第一行，「抖加加」**右侧**，同一水平线 |
| 内容 | **授权与否**常显；**剩余天数**仅在有授权时显示。未授权时只有「未授权」两个字，不带天数 |
| 交互 | 点这段文字 → 弹出输入授权密钥的对话框（与现在未激活时弹的是同一个） |

## 2. 现状（三个地方各说各的）

| 位置 | 现在显示什么 | 问题 |
|---|---|---|
| 顶栏 | 「抖加加」+ `v1.4.17 · 检查更新` | **完全没有授权信息**，用户只能翻到自动关注页最下面才知道 |
| 自动关注页「授权信息」卡片 | 授权状态 / 到期时间（精确到秒）/ 掩码密钥 | 信息全，但藏在页面底部，要滑到最下 |
| 未激活时 | 自动弹「激活授权」对话框 | 每次状态变成未激活都弹（从设置页返回也会弹），有点烦 |

所以本次**只新增入口，不搬迁信息**：下方卡片保留（它是详情，含精确时间与密钥掩码），顶栏只做「一眼可见 + 一键激活」。

## 3. 顶栏设计

### 3.1 布局

```
┌──────────────────────────────────────────────────────┐
│ [图标]  抖加加  已授权 · 剩 365 天        日志   升级 │
│         v1.4.18 · 检查更新                            │
└──────────────────────────────────────────────────────┘
```

- 现状：名字 `tv_app_name`（17sp bold）与版本号 `tv_version`（11sp）在同一个**竖直** LinearLayout 里
- 改法：把第一行包成一个**横向** LinearLayout，里面依次是 `tv_app_name` → `tv_license_badge`（新）
- 新 badge：`11sp`、`maxLines=1`、`ellipsize=end`、`layout_marginStart=8dp`、`gravity=center_vertical`、`clickable=true` + `?attr/selectableItemBackground`（和版本号同款点击反馈）

**宽度核算**（本机 1080px / density 2.177 ≈ 496dp 宽）：

```
496 − 28(左右 padding) − 32(图标) − 34(日志) − 46(升级) ≈ 356dp 可用
抖加加 51dp + 间距 8dp + 徽标最长「已授权 · 剩 365 天」≈ 100dp  ≈ 159dp
```

余量充足。极端情况（系统字号放大到 1.3 倍、剩余天数到 4 位数）仍有余量；真挤了由 `ellipsize=end` 兜住，不会把「日志/升级」顶出屏幕。

### 3.2 文案与颜色

| 授权状态 | 徽标文案 | 颜色 | 备注 |
|---|---|---|---|
| 未授权 | `未授权` | `brand_red` #E1251B | 不带天数（按需求） |
| 已授权、握手正常 | `已授权 · 剩 365 天` | `success_green` #22A94E | |
| 已授权但离线宽限中 | `离线 · 剩 365 天` | `warning_amber` #C98A16 | 提醒「该联网了」，不至于让用户以为授权坏了 |
| 已授权但拿不到到期时间 | `已授权` | `success_green` | 只有状态，无天数 |
| 已授权但已过期 | `已过期` | `brand_red` | 理论分支（服务端会先置 authorized=false），留兜底 |
| 本地占位（LOCAL_PLACEHOLDER） | `已授权（本地）` | `success_green` | 仅 debug/demo 路径会出现 |

天数边界：`≤ 0` 显示「已过期」；`1~999` 原样；不显示「剩 0 天」这种让人困惑的说法。

### 3.3 点击行为

| 当前状态 | 点击后 |
|---|---|
| 未授权 | 弹「激活授权」（现有对话框，一字不改） |
| 已授权 | 弹同一个对话框，但标题改「更换授权密钥」，正文加一句「当前已授权（剩 N 天），输入新密钥会**覆盖**本机授权」 |

已授权时也允许点开是必要的：密钥到期要换发、绑错设备要换绑，现在这些操作只能先卸载重装才能做。

**不做二次确认**：对话框本身要求输入完整 11 位数字，误触不会造成后果；再加一层确认只会让正常换发变啰嗦。

## 4. 剩余天数的口径（这条最容易错，单独说）

现在 `LicenseStatus` 里有两个字段：

| 字段 | 来源 | 问题 |
|---|---|---|
| `remainingDays` | 服务端 `remaining_days`，**握手那一刻的快照**并落盘 | **离线时不会递减**：断网一周，它还会显示「剩 365 天」 |
| `expireAt` | `expires_at` 的绝对时间戳 | 准确，与是否联网无关 |

⇒ **顶栏一律用 `expireAt` 本地算天数，`remainingDays` 只在 `expireAt` 缺失时兜底。**

```kotlin
// 向上取整：距到期 23 小时算「剩 1 天」，不算「剩 0 天」
val days = ceil((expireAt - now) / 86_400_000.0).toLong()
```

跨天刷新：徽标在 `license.state` 变化时重画，但**天数不会自己变**。补两个触发点：

1. `onResume` 用当前 `license.state.value` 重渲染一次（从后台回来就准）；
2. 新增 `Handler` 每小时重渲染一次（App 常驻前台跑整夜时，次日天数会跟上）。

成本：一次字符串拼接 + `setText`，可忽略。

## 6. 顺带需要你定的一件事：未激活的自动弹窗要不要收敛

现在 `setupLicense()` 里，只要状态变成「未激活」就 `showActivationDialog()`。实测有两个副作用：

- 从系统设置页返回（`onResume` 触发复核）时，若仍未激活会**再弹一次**；
- 顶栏有了常显入口之后，自动弹的必要性下降，而反复弹会打断用户。

**推荐**：改成「冷启动后只自动弹一次」（`onCreate` 首帧判一次，或用一次性标记），之后完全靠顶栏点。
**保守**：保持现状不动，只加顶栏（多弹几次但不影响功能）。

我按**推荐**做，除非你说保留现状。

### 剩余天数的取数（计划 §4 的落地）

```kotlin
private fun licenseDaysLeft(status: LicenseStatus): Long? {
    val expireAt = status.expireAt ?: return status.remainingDays   // 只在缺失时退回快照
    return ceil((expireAt - System.currentTimeMillis()) / 86_400_000.0).toLong()
}
```

`remainingDays` 是握手快照、离线不递减；`expireAt` 是绝对时间戳，离线也准。
刷新靠 `onResume` + 每小时一次（App 常驻前台挂机时天数才会跟上）。
