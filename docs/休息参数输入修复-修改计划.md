# 数字输入框「输不进去 / 只留 5」修复 — 修改计划

> 触发：用户反馈「关注多少个休息多少秒 这个不能设置，最大秒是 5，这不对」。
> 目标版本：**vc54 / 1.4.24**。范围：`ui/MainActivity.kt` 的数字框绑定原语 + `content_auto_follow.xml` 一行布局。

---

## 一、日志证据（R-20261030-774556，vc53，370 行）

```
01:59:15.337 I/主界面: 目标关注数量 = 200
02:00:59.865 I/任务引擎: 启动流程「直播间评论关注」：目标 200，每日上限 600，扫描间隔 15 秒
02:03:22.781 I/直播间关注: 到达休息点（每 5 个），休息 55s
02:05:21.496 W/直播间关注: …弹层文案：停止、继续、打开抖音、参数设置、每关注、5、个后休息、秒、开启、
                          目标关注数量、200、每日关注上限、600、扫描间隔、15、分钟
02:08:36 / 02:12:01 到达休息点（每 5 个），休息 55s
```

两个事实：

1. **秒框在界面上是空的** —— dump 里「个后休息」后面直接跟「秒」，中间没有数字。
   这不是没填过，而是**清了之后再也输不进去**。
2. **实际在跑的是 55s**。55 恰好是唯一「首位 ≥ 5」且能落地的一次成功输入；
   30 / 120 / 45 这类首位是 1~4 的值，一个都没留下。

⇒ 「最大秒是 5」不是上限被写成 5（上限是 600），而是**首位小于 5 的数字一敲就被改写成 5**。

## 二、根因

### 2.1 逐键夹取（vc49 引入的回归）

`ui/MainActivity.kt:705` `bindRangedIntField`：

```kotlin
edit.doAfterTextChanged { text ->
    val raw = text?.toString()?.toIntOrNull() ?: return@doAfterTextChanged
    val v = raw.coerceIn(min, max)
    if (v != raw) {
        edit.setText(v.toString())          // ← 在用户按键过程中改写输入框
        edit.setSelection(edit.text?.length ?: 0)
        return@doAfterTextChanged
    }
    onChange(v)
}
```

配合 `REST_SECONDS_MIN = 5`（`MainActivity.kt:1749`）：

| 想输入 | 实际过程 | 结果 |
|---|---|---|
| 30 | 敲 `3` → 3 < 5 → 立刻 `setText("5")`，光标被挪到末尾 → 再敲 `0` 落点已变 | 5 或 50 |
| 120 | 敲 `1` → 立刻变 5 | 5 或 50/520 |
| 45 | 敲 `4` → 立刻变 5 | 5 |
| 55 | 敲 `5` → 5 合法 → 再敲 `5` → 55 | **55 ✓**（所以运行时是 55s） |
| 清空全部 | 空串 `toIntOrNull()` = null → 直接 return，不改设置；一失焦又回填 min | 5 |

**只有 5~9 开头的数能输进去** —— 这就是「最大秒是 5」的成因。

vc49 之前用的是 `bindIntField`（`MainActivity.kt:688`），它**完全不夹取**，所以这是 vc49 加约束时引入的。

### 2.2 同一个原语压在 6 个框上

| 参数 | min ~ max | 现状问题 |
|---|---|---|
| 目标关注数量 | 1 ~ 10000 | 「99999」逐键被改写成 10000，打字被打断 |
| 每日关注上限 | 1 ~ 10000 | 同上 |
| 每关注 N 个 | 1 ~ 500 | min=1，能输；但 `LengthFilter(3)` 会把 1200 截成 120 |
| 每次休息 M 秒 | **5** ~ 600 | **首位 1~4 输不进去（本次故障）** |
| 扫描间隔 | 1 ~ 3600(秒)/60(分) | 手抄了一套同样的逻辑（`bindScanInterval:745`），毛病一样 |
| 养号时长 | `RUN_MINUTES_MIN/MAX` | 同上 |

### 2.3 顺带两个缺陷

- `InputFilter.LengthFilter(max.toString().length)`：**超范围被静默截断**。秒框想输 1200，变成 120
  —— 既不提示，也不等于上限 600。用户以为生效了。
- 直播互动的 5 个框（`commentGapMin/Max`、`likeTrigger`、`likeCountMin/Max`）仍走 `bindIntField`，
  **完全没有范围**：填 0 会让「评论间隔 0 秒 / 点赞 0 个」这类非法配置直接进引擎。

## 三、修法

### 3.1 重写绑定原语：输入过程不夹取，失焦才夹

```kotlin
private fun bindRangedIntField(
    edit: EditText,
    value: Int,
    min: Int,
    max: Int,
    onChange: (Int) -> Unit
) {
    var lastGood = value.coerceIn(min, max)
    edit.setText(lastGood.toString())
    // 多留一位：让「超范围」有机会被失焦时的夹取 + toast 处理，而不是被静默截断
    edit.filters = arrayOf(InputFilter.LengthFilter(max.toString().length + 1))

    edit.doAfterTextChanged { text ->
        val raw = text?.toString()?.toIntOrNull() ?: return@doAfterTextChanged  // 空/中间态：什么都不做
        if (raw in min..max) {            // 合法才落库，且**不改写输入框**
            lastGood = raw
            onChange(raw)
        }
    }

    val commit: () -> Unit = {
        val raw = edit.text?.toString()?.toIntOrNull()
        val v = (raw ?: lastGood).coerceIn(min, max)
        if (raw == null || v != raw) {
            edit.setText(v.toString())
            edit.setSelection(edit.text?.length ?: 0)
            if (raw != null) toast("已调整为 $min ~ $max 范围内的 $v")
        }
        lastGood = v
        onChange(v)
    }

    edit.setOnFocusChangeListener { _, hasFocus -> if (!hasFocus) commit() }
    edit.setOnEditorActionListener { _, _, _ -> commit(); false }   // 键盘「完成」
}
```

三个要点：

1. **输入过程中绝不 `setText`** —— 光标和 IME 组合态不被打断，30/120/45 都能正常敲。
2. **空框 = 未填**，不写 0；失焦回填 `lastGood`（本次会话最后合法值，初值取当前设置）。
3. 非法值期间界面显示的是用户打的数（如 99999），**设置里仍保留上一个合法值**；失焦一次性夹取并 toast。
   这个取舍是刻意的：宁可短暂不一致，也不能打断打字。

### 3.2 扫描间隔合并进同一个原语

把 `bindScanInterval` 里的手抄逻辑删掉，改成：

```kotlin
bindRangedIntField(c.etScanInterval, s.scanIntervalValue,
    Settings.MIN_SCAN_SECONDS.toInt(), Settings.scanValueMax(s.scanIntervalUnit)) { v ->
    store.edit { it.copy(scanIntervalValue = v) }
    LogStore.i(TAG, "扫描间隔 = ${store.current.scanIntervalLabel}")
}
```

单位切换时仍按总时长换算（30 秒 → 1 分钟），换算后重设 `filters` 的位数上限并 `setText`。
注意：位数上限随单位变，所以 `bindRangedIntField` 需要暴露一个「重设范围」的入口，或由调用方在切单位后重新
`setFilters` —— 用后者（`UnitLimit` 回调），改动最小。

### 3.3 范围调整

| 常量 | 现在 | 改为 | 理由 |
|---|---|---|---|
| `REST_SECONDS_MIN` | 5 | **1** | 用户明确说 5 不对；1 秒虽短但无害，主要是不再卡首位 |
| `REST_SECONDS_MAX` | 600 | 600 | 10 分钟够用，不动 |
| `REST_AFTER_N_MIN/MAX` | 1 / 500 | 不动 | |
| 直播互动 5 个框 | 无范围 | 见下 | 填 0 会静默坏事 |

新增（`Settings` 里集中，便于复查）：

```kotlin
const val COMMENT_GAP_MIN = 1;  const val COMMENT_GAP_MAX = 600
const val LIKE_TRIGGER_MIN = 1; const val LIKE_TRIGGER_MAX = 50
const val LIKE_COUNT_MIN = 1;   const val LIKE_COUNT_MAX = 200
```

默认值 5/15/3/5/10 都落在区间内，不会触发迁移。

### 3.4 界面三处小改（`content_auto_follow.xml` + `styles.xml`）

1. **`InputMini` 宽 52 → 60dp**：3 位数（600）+ 字体 1.3 倍时不挤、光标可见。
2. **休息行拆成「标题 + 开关」和「参数」两行**：

```
定时休息                          (●)
每关注 [5] 个后休息 [30] 秒
```

现在这一行既没有「定时休息」四个字，开关又悬在最右，用户不知道那个开关管什么。拆开后高度
32 → 70dp，参数卡从 ~346 增到 ~384dp，页面余量 156dp 仍够一屏。

3. **开关关闭时给一行可见提示**（11sp、`text_tertiary`、默认 `GONE`）：
   「已关闭：跑的过程中不会中途休息」。现在只有 alpha 0.4 的置灰，容易被当成「坏了不能设置」
   —— 这正是这次误解的一部分。

## 五、风险与取舍

- **界面短暂与设置不一致**：非法值会留在框里直到失焦。可接受（换来的是能正常打字）。
- **`LengthFilter` 多留一位**：目标/上限能打 6 位（100000），失焦夹回 10000 —— 比静默截断诚实。
- **悬浮面板不受影响**：`FloatWindowService` 里 `grep restAfterN` 零引用，面板不读写这两个参数；
  日志里那条「每关注、5、个后休息、秒」是主界面的 dump（当时 App 在前台），不是面板自己的控件。
- 本次**不改**动 `FollowFromLiveFlow` 的休息消费逻辑（`restAfterN > 0` 短路仍在，靠范围夹取兜住）。
