# 参数区精简 · 一页布局 — 修改计划

> 目标版本：vc49 / 1.4.19（下一个可用号）
> 前置实测：本机 `PJVOSSHA5TVOY5IZ`，1080×2374 px，density 480（3x）⇒ 逻辑尺寸 **360×791 dp**
> 取证方式：`uiautomator dump` 取真实 bounds（2026-10-31 01:10，vc48 前台）

---

## 0. 一句话结论

删掉 3 项（校准模式、延迟抖动、冗余范围文案）、把 4 行成对参数压成 1 行三列、休息参数合成 1 行内联、授权卡整卡删除，参数卡从 **676dp → ~358dp**，整页总高 **~445dp < 可视 589dp**，默认字号下一屏可见全部参数、不必滚动。

**删的是「配置项」，不是「拟人化行为」**：延迟抖动仍按固定 ±30% 跑，只是不再让用户调（见 §3.2）。

## 1. 已确认的方案选择

| 项 | 决定 |
|---|---|
| 三个死开关（空闲直播互动 / 自动申请连麦 / 下麦后继续干活） | **保留，整行置灰 + 标「暂未生效」**（字段与 SP key 都留着，以后接流程只需 `isEnabled=true`） |
| 「授权信息」卡（3 行） | **整卡删除**，只靠顶栏徽标；到期具体日期补进「点徽标」的弹窗里 |
| 「扫描间隔」 | **保留**（数值 + 秒/分钟），与目标/上限并列成三列 |
| 范围 | 只动「自动关注」页签；养号助手 / 直播互动两页不动 |

## 3. 三个删除项

### 3.1 校准模式（手动校准 / 自动校准）—— 死参数，直接全删

证据：全项目 grep，`calMode` 只有 4 处，全是「存」和「显示」，**没有任何消费方**：

| 位置 | 用途 |
|---|---|
| `data/Settings.kt:12` | 字段定义 |
| `data/SettingsStore.kt:44 / 78` | SP 读写 |
| `ui/MainActivity.kt:495-497` | 段控件绑定 |

`FollowFromLiveFlow` / `TaskEngine` / `Flow` 一次都没读过它。**这个开关从上线起就没接到任何逻辑**，用户点「手动校准」和「自动校准」行为完全一样——删掉零行为变化、零回归风险。

删除范围：布局段控件 + `bindSegmented` 调用 + `Settings.calMode` + `SettingsStore` 的 `KEY_CAL_MODE` 读写。

### 3.2 延迟抖动（%）—— 删配置项，保留行为

诉求是"不需要这个参数"，不是"不要抖动"。降封号是硬验收项（计划 §3.1/§3.2：延迟、落点、滑动、输入节奏全部取区间随机），所以：

- **删**：`et_jitter` 输入框、`Settings.jitterPercent`、MainActivity 绑定、开始提示里的「±30% 抖动」、`TaskEngine` 启动日志里的「抖动 ±X%」
- **留**：`Humanizer` 的随机逻辑不变，幅度改为固定常量 `Settings.HUMANIZE_JITTER = 30`（即当前默认值，行为与 vc48 完全一致）

3 个 `Humanizer(...)` 实例化点统一改为 `Humanizer(Settings.HUMANIZE_JITTER)`：

| 文件 | 行 |
|---|---|
| `engine/TaskEngine.kt` | 94 |
| `service/DebugChannel.kt` | 126 |
| `ui/MainActivity.kt` | 1537 |

（`DebugChannel.kt:363` 原本就是 `Humanizer(0)`，用于调试精确点击，不动。）

### 3.3 「范围 1 ~ 10000」两处副文案 —— 删

`bindRangedIntField` 已经在失焦时夹取并 toast「已调整为 1 ~ 10000 范围内的 X」，输入框下方的静态文案只是占位说明，删掉不影响任何约束。

### 3.4 三个死开关 —— 按「保留 + 标暂未生效」处理

grep 除 `Settings.kt` / `SettingsStore.kt` / `MainActivity.kt` 之外的全部源码，以下三个字段**零消费方**：

| 字段 | 界面文案 | 引擎引用 |
|---|---|---|
| `idleLive` | 空闲时直播互动 | **0 处** |
| `applyMic` | 自动申请连麦 | **0 处** |
| `continueAfterMic` | 下麦后继续干活 | **0 处**（`LiveInteractFlow` 用的是另一个字段 `micRequest`） |

对照：同批的 `intervalRest` / `restAfterN` / `restSeconds` 在 `FollowFromLiveFlow:302-310` 真实生效。

**处理（已确认）**：保留字段、SP key、控件 id，只把界面改成"明示暂未生效"的形态，避免用户以为开了就有用：

- 标题：14sp → `text_secondary`（灰）
- 尾部注记：「暂未生效」11sp `text_tertiary`，紧跟在标题后
- `SwitchMaterial.isEnabled = false`、`alpha = 0.5`
- 行高仍 32dp

以后接流程时，把 `isEnabled` 打开、删掉注记即可，无需改代码结构。

## 4. 新布局

### 4.1 线框（360dp 宽，卡片内宽 304dp）

```
┌─ 权限设置 ● ● ● ───────────────────────┐   77dp
└────────────────────────────────────────┘
┌─ 参数设置 ─────────────────────────────┐
│                                         │
│  目标关注数量   每日关注上限   扫描间隔   │   label 12sp
│  ┌────────┐  ┌────────┐  ┌──────────┐  │
│  │  200   │  │  200   │  │    30    │  │   44dp 输入
│  └────────┘  └────────┘  └──────────┘  │
│                          ┌───┬────┐    │
│                          │秒 │分钟│    │   28dp 单位段
│                          └───┴────┘    │
│                                         │
│  每关注 [ 5 ] 个后休息 [ 30 ] 秒  (●)   │   36dp 内联
│                                         │
│  空闲时直播互动 暂未生效      (○ 灰)     │   32dp
│  自动申请连麦   暂未生效      (○ 灰)     │   32dp
│  下麦后继续干活 暂未生效      (○ 灰)     │   32dp
│                                         │
│  💡 评论参数请在「直播互动」页签配置 ›   │   30dp
└────────────────────────────────────────┘
（授权信息卡整卡删除；到期日期移到点徽标的弹窗里）
```

### 4.2 三列核心行（关键改动）

现在「目标 / 上限」各占半行、扫描间隔挤在旁边，纵向要两行。改成**一行三列**：

| 列 | 控件 | 宽 | 文案宽（12sp） | 余量 |
|---|---|---|---|---|
| 1 | `et_follow_target` | 96dp | 72dp | 24dp |
| 2 | `et_daily_limit` | 96dp | 72dp | 24dp |
| 3 | `et_scan_interval` + `seg_interval_sec/min` | 96dp | 48dp（段内 2 字 = 24dp/格） | 够 |

「10000」5 位数字 16sp ≈ 45dp + 左右 padding 24dp = 69dp < 96dp ✓
窄列下段控件字号从 14sp 降到 **12sp**（新增 `SegMini` 样式，高 28dp）。

### 4.3 定时休息合并成内联一行

原为「label + 一行两框」（106dp），改为单行内联（36dp）：

```
[每关注] 五(5)个 [个后休息] 三十(30)秒 [switch]
```

- 新增样式 `InputMini`：`width=52dp, height=32dp, textSize=14sp, gravity=center, background=bg_input, inputType=number`
- 三个文字标签 12sp、`text_secondary`，`gravity=center_vertical`
- 开关关掉时两个输入框 `isEnabled=false` + `alpha=0.4`（现在没做，合并后视觉上更需要）

### 4.4 三个死开关行

单行「标题 + 暂未生效注记 + 置灰开关」，见 §3.4。相比现在的「标题 + 副文案 + 开关」省 6dp/行，主要是去掉误导。

配置引导条保留（评论参数确实在另一个页签），但从 34dp 收到 30dp、字号 12sp 不变。

### 4.5 高度测算

| 块 | 旧 | 新 |
|---|---|---|
| 卡片 padding（上下 16dp） | 32 | 32 |
| 「参数设置」标题 | 20 | 20 |
| 校准模式 label + 段控件 | 60（含 margin） | **0** |
| 三列核心行（label+框+单位段） | 两行共 168 | 110 |
| 定时休息 | 106 | 50 |
| 开关 3 行 | 114 | 96 |
| 配置引导条 | 34 | 38 |
| 范围文案 ×2 | 30 | **0** |
| **参数卡合计** | **676 dp** | **~346 dp** |

页级总高：权限卡 77 + 间距 10 + 参数卡 346 = **433 dp** vs 可视 **589 dp**，**余 156 dp**。

### 一个与本次改动无关的现象（已确认非回归）

覆盖安装（`install -r`）后无障碍点变红，`dumpsys accessibility` 却显示 `Bound services:{…抖加加 自动化…}`。
原因写在 `DggAccessibilityService.onCreate` 的注释里：**HyperOS 覆盖安装/强杀后不一定回调
`onServiceConnected`**，于是 `current` 仍为 null ⇒ 三合一判据判「未授权」。
重新绑一次（清空 `enabled_accessibility_services` 再写回）后立刻变绿。**不是 vc49 引入的**，
但说明这条判据对「系统有记录、实例没起来」是敏感的——它判的正是"能不能用"，方向没错。
