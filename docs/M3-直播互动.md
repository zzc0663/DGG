# M3 · 直播互动（发评论 / 点赞 / 申请连麦）

> 状态：**已真机跑通**（2026-10-27，OPPO PLB110 / Android 17 / 抖音 40.8.0）
> 入口：抖关关 → 「直播互动」页签 → 「开始服务」

## 1. 范围

| 做 | 不做 |
|---|---|
| 在**用户已进入**的直播间里按随机间隔发评论 | 自己找直播间、切直播间、离开直播间 |
| 复制最新评论 / 发预设话术两种模式 | 发送带导流、广告、联系方式的内容 |
| 每 N 条评论触发一次点赞（次数随机） | 赠送任何付费礼物 |
| 可选：申请一次连麦 | 反复申请连麦、自动确认任何弹窗 |

和 M2 一样：**前提是用户自己进好直播间**。这是产品决策，不是实现偷懒——
自动化「找房间」是最容易被判定为机器的行为，而且容易把你带进不该进的地方。

## 2. 一轮的时序

```
确认在直播间（连续 2 次） → 可选申请连麦（只一次）
  → 生成评论内容（复制 / 预设）
  → 随机等待 5~15s（分片等待，每片都查暂停/停止/风控）
  → 点输入框 → 按 isEditable 找真正的 EditText → 逐字输入
  → 等「发送」按钮 → 点击 → 再查一次风控（「评论过快」是闪一下就消失的 toast）
  → 校验输入区回到占位态（= 已提交）
  → 发满 N 条 → 点赞（双击空白画面 M 次，M 随机）
```

没有总量目标，跑到手动停止为止。状态栏与通知显示「已发评论 N」。

## 3. 三条硬约束（降封号项，不是可选项）

1. **评论内容是最大风险，不是行为本身。**
   复制模式只搬别人的**正文**（不是整行，避免把自己的昵称一起发），并剔除系统提示、
   导流广告、纯表情、超长/超短内容。实测第一次联调就抄到一条「点点关注+18000元」——
   正好从「关注我」这类关键词的空隙漏了过去，事后补了 `SPAM_HINTS`。
2. **命中「评论太快/操作频繁/安全验证」立刻停机，禁止重试。**
   `AnomalyGuard` 的短语表加了直播互动专项词；`sendComment` 点完发送会**立刻多查一次**，
   不等下一次 settle。
3. **连麦只申请一次，且不自动点任何确认弹窗。**
   反复申请是这个直播间里最扎眼的异常；而自动确认意味着脚本在不知道弹窗内容的情况下同意任何东西。

## 4. 定位项（40.8.0 实测）

| 目标名 | 配置 | 实测结构 |
|---|---|---|
| `comment_input` | `textContains "说点什么"` | `EditText [72,2188][480,2302] text='说点什么...' desc='说点什么...'`（**本身就是可编辑节点**） |
| `live_comment_send` | `text "发送"` | 打开输入面板后才出现，实测点中 `(927,1247)` |
| `live_comment_line` | `textContains "："` | 评论整行「昵称：正文」 |
| `live_mic_button` | `descContains "连线"` | **该直播间没有**（只有「更多面板 按钮」），流程记警告后跳过 |

### 4.1 ⚠️ 「小心心」是付费礼物，不是点赞

直播间底栏只有四颗：`表情入口` / `小心心` / `礼物` / `更多面板 按钮`。
其中 **`desc='小心心'` 是 1 钻付费礼物**，点下去弹「送出小心心礼物需支付1钻，确定支付？」。
按「心形 = 点赞」的直觉去挑控件会花掉用户的钱。

处置：
- `live_like_button` 这个目标**从配置里删掉了**，不留任何指向它的可能；
- 更根本的防线在 `Actions.tapNode` —— 见到 text/desc 里有「小心心/支付/充值/购买/打赏/送礼」
  一律**拒点**并记 error。这条守卫放在最底层，因为只要有一条流程漏判，后果就是真实扣款。

### 4.2 点赞 = 双击空白画面

40.8.0 直播间节点树里没有任何带「点赞」文案的可点控件（647 个节点全扫过），
所以点赞只能双击画面。落点先过 `Actions.freePointIn()`：
在画面上部中间区域随机取点，**校验底下没有可点控件**（礼物飘屏、送礼人卡片都压在视频上），
取不到空白点就这一轮不点赞——宁可少点，不盲点。

**局限（不掩盖）**：点赞是否真的生效**无法定量验证**。
万人房的「本场点赞」每秒涨几百，我们那几下被自然增长完全淹没（实测 938.1 万 → 948.4 万，
12 秒涨 10 万，与是否双击无关）。所以日志写的是「已发出 N 次点赞手势」，不宣称成功。

## 6. 已知限制

1. **点赞有效性无法定量验证**（见 §4.2）。双击偶尔会打开浮层（实测一次），
   流程会按返回关掉并继续；如果某个直播间里双击必然开浮层，建议在设置里关掉「评论时自动点赞」。
2. **复制评论仍有内容风险**：过滤器只能挡「明显的」广告/导流。想彻底可控就用「预设评论」。
   话术库在 `assets/live_comments.json`，可用 `<app>/files/live_comments.json` 覆盖。
3. **「系统推荐」进入方式未实现**：该选项需要「首页推荐流里识别直播卡片」的定位特征，
   这一版没校准，选中后只记一条警告并按「手动进入」继续（不假装支持）。
4. **连麦**只点一次且不确认弹窗；多数直播间底栏没有独立连线入口，实际会跳过。
5. `waitFor` 轮询仍是每次全树 `find`（约 1.4s/次），会让「等发送按钮」多花 1~2 秒。
   不影响正确性，属后续优化项。

## 7. 怎么验收

1. 手机手动进入一个**人多、评论在滚**的直播间；
2. 抖关关 → 直播互动 → 把「评论发送间隔」调成 5~15 秒、「每发几条评论触发点赞」设 3；
3. 点「开始服务」→ 确认弹窗里应显示当前参数（间隔/模式/点赞次数）；
4. 看状态栏「已发评论 N」是否递增；运行日志里能看到每条的正文；
5. 屏幕被自动操作是正常的；随时用悬浮窗「停止」或通知栏停止。
