# 把直播互动参数并进自动关注页 — 修改计划

> 目标：**一个页签就是一次完整的「关注 + 评论互动」配置**，不用再跨页签搬参数。
> 触发：用户「直播互动参数是否可以集成到自动关注页面来，自动关注页面下方做直播互动的参数设置」。

---

## 一、现状

三个页签是三个同级 `ScrollView`，靠 `visibility` 切换（不是 ViewPager）：

```
tabs       = [tab_auto, tab_nurture, tab_live]        // 每列 layout_weight=1
pages      = [contentAuto.root, contentNurture.root, contentLive.root]
selectTab(i) → 只切 visibility
```

| 页签 | 现有卡片 | 性质 |
|---|---|---|
| 自动关注 `content_auto_follow.xml` | 权限卡 → 参数卡（目标/上限/扫描间隔/定时休息/3 个死开关）→ 「去配置」提示行 | 配置 |
| 养号助手 `content_nurture.xml` | 权限卡 → 运行时长/模式/节奏 → 概率 → 标签 | 配置 |
| 直播互动 `content_live.xml` | 权限卡 → 直播间进入方式 → 互动设置 → 评论模式 | **全部是配置，没有任何运行时内容** |

也就是说：**直播互动页 = 3 张参数卡 + 一张没用的权限卡**，搬走之后这一页是空的。

真机高度（360×791dp，可视内容区 **589dp**）：

| 块 | 高度 |
|---|---|
| 权限卡 | ~77 |
| 自动关注参数卡（vc54 后含休息标题行） | ~384 |
| 底部「评论参数请在直播互动页签配置」提示 | ~60 |
| **自动关注页小计** | **~530** |
| 进入方式卡 | ~92 |
| 互动设置卡 | ~290 |
| 评论模式卡 | ~160 |
| **直播三卡小计（含 3×10 间距）** | **~570** |

合起来约 **1100dp ≈ 1.9 屏** —— 集成后**必然要滚动**，这跟 vc49「一页放下」的目标相反。
取舍：参数全在一个页签 ⇒ 用滚动换「不用切页签」。

## 二、目标结构（三卡合并成一张「直播互动」卡）

三张卡（进入方式 / 互动设置 / 评论模式）合并为**一张**，每行「左标签 + 右控件」，去掉全部副文案：

```
[自动关注]  [养号助手]                     ← 两页签，各占 50%

权限卡
┌ 参数设置 ────────────────┐
│ 目标关注数量 / 每日上限 / 扫描间隔  │
│ 定时休息  (●)                     │
│ 每关注 [5] 个后休息 [30] 秒        │
│ 空闲时直播互动 暂未生效 (○)         │
└──────────────────────────┘
┌ 直播互动 ────────────────┐
│ 进入方式   [手动进入][系统推荐]        │ 28
│ 评论间隔   [5] ~ [15] 秒              │ 32
│ 评论模式   [复制评论][预设评论]        │ 28
│ 启动后自动复制直播间最新评论并发送      │ 16  (11sp 一行)
│ 自动申请连麦                    (○)   │ 20
│ 评论时自动点赞                  (●)   │ 20
│ 点赞触发   [3] 条评论后                │ 32
│ 每次点赞   [5] ~ [10] 个               │ 32
└──────────────────────────────┘
```

底部那行「💡 评论参数请在『直播互动』页签配置 ›」**整行删除**（参数就在下面了）。

**高度账**

| 块 | 原 | 上一版方案 | 本次（合并） |
|---|---|---|---|
| 进入方式卡 | ~92 | 56 | — 并入 |
| 互动设置卡 | ~290 | 202 | — 并入 |
| 评论模式卡 | ~160 | 78 | — 并入 |
| **三卡合计（含卡间距）** | **~570** | ~366 | **~292** |
| 整合后整页 | ~1100（1.9 屏） | ~900 | **~830（1.4 屏）** |

292 的构成：8 行内容 208 + 行距 8×7 = 56 + 卡内边距 14×2 = 28。
对比上一版，省下来的 74 主要来自**两张卡的 padding 与 margin（2×38）** 和**四条副文案（4×15）**。

去掉的是什么：三张卡的分组标题（「直播间进入方式」「互动设置」「评论模式」）和每条开关的说明小字
（如「开始互动后自动点击连线并申请」）。这些原来占 ~74dp，且内容都能从标签本身读懂；
真要保留说明，只能放回副文案，一张卡就回涨到 366 以上。

## 三、改动清单

### 3.1 `res/layout/content_auto_follow.xml`

- 在参数卡之后、原提示行位置，新建**一张** `CardBox`（标题「直播互动」），把直播互动的控件逐行放进去。
  **id 一个都不改**（`seg_enter_manual/recommend`、`sw_mic_request`、`et_comment_gap_min/max`、
  `sw_like_on_comment`、`et_like_trigger`、`et_like_count_min/max`、`seg_comment_copy/preset`、
  `tv_comment_mode_desc`），这样 `bindLive()` 只换 `binding.contentLive` → `binding.contentAuto`。
- 删除「💡 评论参数请在…」整个 `LinearLayout`（含 `tv_go_config`）。
- 这张卡给 `android:id="@+id/card_live_params"`，供养号页「评论配置 ›」跳转定位；
  卡下方由根的 `paddingBottom`（20 → **96dp**）兜住 FAB。
- **原来的三张卡整组丢弃**（`content_live.xml` 直接删文件），不再保留分组标题。

**逐行规格（这张卡是本次唯一的布局改动）**

| # | 行内容 | 控件 | 高 | 内宽占用（卡内 272dp） |
|---|---|---|---|---|
| 1 | `进入方式` + `[手动进入][系统推荐]` | TxtFieldLabel + 2×SegChip | 28 | 48+8+68+6+68 = **198** |
| 2 | `评论间隔` + `[5] ~ [15] 秒` | label + 2×InputMini + `~` + `秒` | 32 | 48+6+60+6+8+6+60+6+12 = **212** |
| 3 | `评论模式` + `[复制评论][预设评论]` | label + 2×SegChip | 28 | 48+8+68+6+68 = **198** |
| 4 | 说明（动态文案） | `tv_comment_mode_desc` 改 `TxtHint` 单行 `ellipsize=end` | 16 | — |
| 5 | `自动申请连麦` + 开关 | label + `sw_mic_request` | 20 | 72+52 = 124 |
| 6 | `评论时自动点赞` + 开关 | label + `sw_like_on_comment` | 20 | 84+52 = 136 |
| 7 | `点赞触发` + `[3] 条评论后` | label + InputMini + 文字 | 32 | 48+6+60+6+60 = **180** |
| 8 | `每次点赞` + `[5] ~ [10] 个` | label + 2×InputMini + `~` + `个` | 32 | 48+6+60+6+8+6+60+6+12 = **212** |

- 行间距统一 **8dp**（原来 14~18dp），卡 padding 14dp。
- 6 个数字框全部用 `InputMini`（60×32），字号 12sp 的标签 + 14sp 的数字。
- ⚠️ **不能把「点赞触发」和「每次点赞」并成一行**：两组数字框 + 中文标签要 ~290dp，
  超过 272dp 的内宽，1.3 倍字号必挤爆。这两行是本次的宽度瓶颈。
- ⚠️ chip 必须新样式 `SegChip`（`wrap_content` + 左右 10dp 内边距），
  **不能用 `SegItem`**（它是 `width=0dp` + `weight=1`，两个 chip 会被撑成半屏）。
- `tv_comment_mode_desc` 保留 id 与动态文案逻辑，只把容器由 `bg_hint` 灰底块换成 `TxtHint` 文本。


### 3.2 `res/layout/activity_main.xml`

- 删 `tab_live` + `indicator_live` 所在的第三个 `LinearLayout`（`layout_weight=1`）。
  剩两列各占 50%，其余不用动。
- 删 `<include android:id="@+id/content_live" …>`。

### 3.3 `ui/MainActivity.kt`

| 位置 | 改动 |
|---|---|
| `setupTabs()` | `tabs/indicators/pages` 三项 → 两项 |
| `bindLive(s)` | `binding.contentLive` → `binding.contentAuto` |
| `setupPermissionCards()` / `refreshPermissionState()` | 三张 `permCard` → 两张（`contentAuto`、`contentNurture`） |
| `tvGoConfig` 监听 | 删除（控件已不存在） |
| `contentNurture.tvCommentConfig` | 原来 `selectTab(2)` → 改成 `selectTab(0)` + 滚到「评论模式」卡 |
| `TAB_NAMES` | `["自动关注", "养号助手", "直播互动"]` → 两项 |
| `currentTab` 初值 / `onSaveInstanceState` | 检查是否有硬编码 `2` |

滚到卡片：用 `binding.contentAuto.cardLiveParams.smoothScrollTo` 等价写法
（`binding.contentAuto.root.post { root.smoothScrollTo(0, card.top) }`，`post` 里取 `top` 避免布局未完成）。

### 3.4 删除 `res/layout/content_live.xml`

git 里有历史，需要恢复时 `git revert` 或 `git show <commit>:path` 即可。

### 3.5 样式

`res/values/styles.xml` 新增 `SegChip`（基于 `SegMini` 的尺寸，但宽度 `wrap_content`）：

```xml
<style name="SegChip">
    <item name="android:layout_width">wrap_content</item>
    <item name="android:layout_height">28dp</item>
    <item name="android:paddingStart">10dp</item>
    <item name="android:paddingEnd">10dp</item>
    <item name="android:gravity">center</item>
    <item name="android:textSize">12sp</item>
    <item name="android:textColor">@color/text_primary</item>
    <item name="android:background">@drawable/bg_chip_normal</item>
    <item name="android:clickable">true</item>
    <item name="android:focusable">true</item>
</style>
```

选中态沿用 `SegMiniSelected` 的做法（`bg_segment_selected` + 白字粗体），
可直接在代码里 `setBackgroundResource` 切换，`bindSegmented` 已经有这套逻辑 ——
只需确认它用 `grouped` 参数控制圆角，chip 场景传 `grouped = false`。

## 四、风险

1. **id 冲突**：`content_live.xml` 删掉后，`seg_enter_manual` 等 id 在全局唯一；但 `perm_card`
   两个布局都有（include 时 id 由 include 覆盖，现有代码就是这么用的），删掉一个不影响。
2. **`selectTab(2)` 越界**：所有 `selectTab(2)` 必须清干净，否则 `pages[2]` 直接
   `IndexOutOfBoundsException` 崩在点击事件里。grep 关键：`selectTab(2)`、`TAB_NAMES`、`currentTab`。
3. **FAB 遮挡**：FAB 在 `FrameLayout` 外、固定在右下，滚动到底时直播卡最后两行可能被压住 ——
   给内容底部 `paddingBottom` 加到 96dp（现在是 20dp）。
4. **状态保存**：`currentTab` 若存了 2（上个版本），恢复时要夹到 `pages.lastIndex`。
5. **bindLive 早于布局完成**：`bindAllSettings()` 里没涉及测量，安全。
6. 页面变长后，权限卡滚出屏幕 → 用户在页面底部看不到「无障碍是红的」。建议：**权限卡保持
   在页面最顶部不动**（现状），并在「开始服务」被点且权限缺失时 toast 提示（已有）。

## 七、实施记录（vc55 / 1.4.25，2026-10-31）

### 7.1 计划外发现（必须记）

**「直播互动」页签不只是参数页，它还是 M3 的启动入口。** `confirmAndStart()` 按 `currentTab` 分发流程：

```kotlin
when (currentTab) {
    TAB_AUTO    -> confirmFollow()
    TAB_NURTURE -> confirmNurture()
    TAB_LIVE    -> confirmLiveInteract()   // 删掉页签后这一支永远走不到
}
```

底部「开始服务」是**所有页签共用**的一个按钮，所以「删掉页签」等于**删掉直播互动的运行方式**。
计划阶段我按「页面里只有参数卡」判定为空壳，这一点是错的。

处理：在直播卡末尾加一行 `tv_start_live`「只跑直播互动 ›」（12sp 品牌红、右对齐、上边距 12dp），
直接调 `confirmLiveInteract()`；`confirmAndStart()` 的 `TAB_LIVE` 分支与常量一并删除，`currentTab` 只剩 0/1。
授权门禁不受影响：`confirmLiveInteract → startFlow → EngineController.start()` 里仍有
`LicenseGate.isAuthorized()` 那道唯一的硬门禁。
