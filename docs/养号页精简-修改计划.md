# 养号助手页精简 — 修改计划

> 触发：用户「养号的界面也需要精简」。
> 现状：**约 993dp ≈ 1.7 屏**（可视 589dp），四张卡里三张是「一张卡只放 1~2 个参数」。
> 目标版本：**vc56 / 1.4.26**。

---

## 一、现状盘点（360×791dp，可视 589dp）

```
权限卡                                   77
┌ 运行设置 ─────────────────┐
│ 运行时长（分钟，1-1440）        │   ← label 独占一行
│ [60]                            │
│ 停留节奏（每条视频看多久）      │
│ [慢][标准][快]                  │
│ 标准节奏下每条约看 1.5～90 秒…  │   ← 两行灰字
└───────────────────────────┘  234
┌ 养号模式 ─────────────────┐
│ [刷视频养号][垂直养号][首页连播] │
│ 刷视频养号：自己上下滑…（灰底块）│   ← 两行
└───────────────────────────┘  170
┌ 操作概率 ─── 评论配置 › ────┐
│ 点赞倾向（基线）          40%   │  ┐
│ [——————O——————]              │  │
│ 收藏概率                  15%   │  │ 每项
│ [————O———————]               │  │ = label 行 32
│ 评论概率                  10%   │  │ + 滑块 48
│ [———O————————]                │  │ = 80dp
│ 转发概率                   5%   │  │
│ [—O——————————]                │  ┘
│ 文案标签加权（未配置）      [编辑] │
│ 视频文案命中标签时…（灰字两行）  │
│ ⚠ 为避免触发风控…               │
└───────────────────────────┘  450
卡间距 3×10 + 页面上下 padding 32    62
─────────────────────────────────
                     合计  ≈ 993dp（1.7 屏）
```

问题很集中：

1. **每个滑块占 80dp** —— label 一行、滑块一行，4 个就是 320dp，占整页 1/3。
2. **说明文字全是两行灰字**（3 处，共 ~90dp），信息密度极低。
3. **运行时长** 用 44dp 的 `InputBox` 独占一行，标签还带「（分钟，1-1440）」。
4. **权限卡在三处重复**（改版前三个页签各一张），养号页这张 77dp 基本没人看。

---

## 二、精简方案

### 2.1 运行设置卡：234 → **150**

```
┌ 运行设置 ─────────────────┐
│ 运行时长  [60] 分钟            │   ← 内联一行，InputMini
│ 停留节奏  [慢][标准][快]        │   ← 内联一行，SegChip
│ 标准约 2~12 秒/条，慢 ×1.6、快 ×0.6 │   ← 说明压成一行 11sp
└───────────────────────────┘
```

- 「运行时长（分钟，1-1440）」的括号删掉（范围由夹取 + toast 兜，和 vc54 改的数字框一致）。
- 节奏说明从「标准节奏下每条约看 1.5～90 秒（多数 2～12 秒），慢/快分别把整体时长乘 1.6 / 0.6」
  压成「标准约 2~12 秒/条，慢 ×1.6、快 ×0.6」，两行 → 一行。

### 2.2 养号模式卡：170 → **122**

```
┌ 养号模式 ─────────────────┐
│ [刷视频养号][垂直养号][首页连播] │   ← 38dp 分段（保持原样，三格等分）
│ 刷视频养号：自己上下滑推荐流…    │   ← 单行 11sp，省略号截断
└───────────────────────────┘
```

- 模式说明去掉灰底块（`bg_hint` + 上下 9dp padding = 18dp 纯装饰），改成 `TxtHint` 单行。
- 说明文案本身是动态的（`modeDescriptions`），保留 `tv_mode_desc` 这个 id，只改样式与 `maxLines=1`。

### 2.3 操作概率卡：450 → **334**（关键改动）

四个滑块改成「标签 + 滑块 + 数值」**一行**：

```
┌ 操作概率 ─── 评论配置 › ────┐
│ 点赞   [————O————]      40% │  ┐
│ 收藏   [——O——————]      15% │  │ 每行 48dp
│ 评论   [—O———————]      10% │  │ （原来 80dp）
│ 转发   [O————————]       5% │  ┘
│ 文案标签加权（未配置）      [编辑] │
│ 命中标签按 基线×(1+加成)，最高 60% │
│ ⚠ 点赞最多 60%，其余每项最多 40%  │
└───────────────────────────┘
```

- 行宽分配（卡内 272dp）：标签 48 + 8 + 滑块 `0dp/weight=1`（≈170）+ 8 + 百分比 38。
- 滑块 `labelBehavior` 本来就是 `gone`，不存在标签遮挡问题。
- 「文案标签加权」那行的说明从两行压成一行。

## 五、风险

1. **`SegItem` → `SegChip` 后不再等分**：三个选项（刷视频养号/垂直养号/首页连播）宽度不一，
   一行放「标题 + 三个 chip」是放不下的（48 + 80 + 68 + 68 + 间距 = 276 > 272），
   所以**养号模式那一行保持独立一行、仍用 `SegItem` 等分**，只把节奏的三个（2 字）改 `SegChip` 内联。
2. **滑块变短**：170dp 分 12 档（0~60，step 5），每档 14dp，能精确拖到；但手指粗的用户会比现在难。
   这是本次最大的可用性代价，建议先按此版跑一轮再定。
3. **`tv_mode_desc` 单行截断**：三种模式的说明长度不同，「首页连播」那条最长，会被省略号截掉尾巴。
4. **`InputMini` 只有 60dp**：运行时长最大 1440（4 位），14sp 下 4 位数约 33dp，1.3 倍字号约 43dp，
   仍放得下；但 `LengthFilter` 是 6 位，打「99999」会被夹到 1440 并 toast。
5. 删除权限卡后，**「忽略电池优化」入口只剩自动关注页那一处**，养号页不再能直接点（已确认接受）。

## 六、已确认的决策

| # | 决策 | 取舍 |

### 8.2 发现并修复的缺陷（vc59）

**1.3 倍字号下，养号页最后一行被悬浮菜单按钮压住。**

```
「⚠ 点赞最多 60%，其余每项最多 40%」 [84,1967][996,2026]
fab_menu                          [870,1936][1038,2104]
```

`content_nurture.xml` 根的 `paddingBottom` 写的是 **20dp**，而自动关注页是 **96dp** ——
vc56 整页重写时漏同步了。1.0 倍字号下内容较矮、碰巧不撞，1.3 倍把最后一行顶到了 FAB 下面。

修法：20dp → **96dp**。复测 1.3 倍下最后一行 bottom=**1798**，FAB 从 1936 起，间距 46dp。

🔴 教训：**「1.0 倍能看」不等于「不遮挡」**。FAB 是浮在 FrameLayout 上的，
只有滚动到最底部时才会暴露重叠，而且内容高度随 font_scale 变化 ——
两页的 `paddingBottom` 必须一致地留到 ≥96dp（FAB 高 56dp + 上下余量）。

### 8.3 已知但不改

`tv_mode_desc`（养号模式说明）在 1.3 倍字号下被 `ellipsize` 截断，末尾「点赞」看不到 ——
这是 vc56「压成单行」的必然代价，不是新问题。要看全文只能换行（+44dp）。
