## 2. 密钥与密码位置

```text
D:\Documents\android\DGG\.signing\dgg-release.jks
D:\Documents\android\DGG\keystore.properties
```

- 两者都已被 `.gitignore` 忽略，**不要提交、不要发群、不要放进 APK**。
- `keystore.properties` 含 store/key 密码；请离线备份到密码管理器或加密介质。
- 丢失 keystore 后无法给已安装用户发 OTA；只能换新包名/新安装。
- 泄露 keystore 后任何人都能签发可覆盖你应用的更新包。

## 3. 构建 release

```powershell
$env:JAVA_HOME='C:\Users\zc\.gradle\jdks\eclipse_adoptium-21-amd64-windows.2'
$env:Path="$env:JAVA_HOME\bin;$env:Path"
.\gradlew.bat assembleRelease `
  -x lintVitalAnalyzeRelease -x lintVitalRelease `
  -Pdgg.applicationId=com.example.dgg `
  -Pdgg.apiBaseUrl=https://your-api.example.com/ `
  --console=plain --no-daemon
```

- `dgg.apiBaseUrl` 必须是真实 HTTPS 域名；不传则用 `https://api.example.com/`，App 无法连接。
- 跳过 lint 是因为本机网络无法拉取 lint 依赖；CI 环境应恢复 lint 并作为门禁。
- 产物：`app/build/outputs/apk/release/app-release.apk`。

校验：

```powershell
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
aapt2 dump badging app/build/outputs/apk/release/app-release.apk
```

## 4. 与 Debug 签名的关系

当前测试机安装的是 Debug 签名 APK。Release 签名不同，**无法覆盖安装**：

```powershell
adb uninstall com.example.dgg
adb install app/build/outputs/apk/release/app-release.apk
```

这会清空 App 本地数据（包括设备令牌），需要重新激活。正式发布前执行一次即可。

## 5. 服务端登记

服务端应配置同一个证书指纹：

```env
APP_PACKAGE=com.example.dgg
APP_SIGNING_CERT_SHA256=59927d81b26f650a29e7fbab1c991e58c1ceb2546c5265ac63864651900e318d
```

之后上传 APK 时，服务端会拒绝证书不一致的包。
